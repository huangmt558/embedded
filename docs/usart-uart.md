# USART／UART 异步串口

[返回目录](../README.md)

**异步串口通过起始位确定一帧的开始，通过约定的波特率确定位时间，通过帧格式确定怎样收发。**

UART 指通用异步收发器；USART 还支持同步通信。本篇以 **STM32F103 的 USART 工作在普通异步、8N1 模式**为例，先讨论 TX／RX、帧格式、位时间和轮询／中断接收。[RM0008：USART][rm0008]

## 1. TX、RX 怎样连接

| 引脚 | 作用 | 两块板之间的连接 |
| --- | --- | --- |
| TX | 发送数据 | 板 A 的 TX → 板 B 的 RX |
| RX | 接收数据 | 板 A 的 RX ← 板 B 的 TX |
| GND | 共同的电压参考 | 板 A 的 GND ↔ 板 B 的 GND |

在两块板以兼容的逻辑电平直接连接的场景中，**TX、RX 交叉连接，并共地**。[ST 两板串口通信示例][uart-start]

```text
板 A                    板 B
TX ───────────────────→ RX
RX ←─────────────────── TX
GND ─────────────────── GND
```

TX 和 RX 是两个方向的数据通路，普通异步串口可同时发送和接收。

## 2. 8N1 表示什么

| 配置 | 含义 |
| --- | --- |
| 8 | 8 个数据位 |
| N | 无奇偶校验位，None |
| 1 | 1 个停止位 |

**每帧还有 1 个起始位，它没有写在“8N1”这个名称里。**

```text
1 位起始位 + 8 位数据位 + 0 位校验位 + 1 位停止位 = 10 位
```

因此，发送 **1 字节有效数据**，在线路上占用 **10 个位时间**。这 10 位已经包括起始位，不再另外加一位。[RM0008：字符描述][rm0008]

在本篇的普通逻辑电平串口中：

- 空闲状态：高电平。
- 起始位：低电平，持续一个位时间。
- 停止位：高电平，8N1 下持续一个位时间。

<details>
<summary>以发送 0x01 为例，一帧的内容是什么？</summary>

F103 的 USART 先发送数据的低位，即 D0 先于 D7。[RM0008：发送器][rm0008]

`0x01` 按 D7～D0 写成二进制是 `00000001`，实际数据位的发送顺序是 `1、0、0、0、0、0、0、0`。

| 阶段 | 位数 | 按时间顺序出现的电平 |
| --- | ---: | --- |
| 起始位 | 1 | 0 |
| 数据位 D0～D7 | 8 | 1、0、0、0、0、0、0、0 |
| 停止位 | 1 | 1 |

空闲电平是传输前后的状态，不是每帧额外固定增加的一位；连续发送时，可以在停止位结束后开始下一帧。

</details>

## 3. 波特率怎样换算成每秒的字节数

在常见的二进制异步串口中，一个码元承载一位，所以 **115200 波特对应 115200 bit/s 的线路速率**。这是传输速率，不表示程序一定持续发送。

这些位包括起始位、数据位、可选校验位和停止位，不能全部算作有效数据。

### 本轮问答中的计算

以 `115200、8N1` 为例：

```text
一个位时间 = 1 / 115200 秒 ≈ 8.68 μs

发送一帧的时间 = 10 / 115200 秒 ≈ 86.8 μs
一帧承载的有效数据 = 8 位 = 1 字节

理论有效字节率 = 115200 / 10 = 11520 字节/秒
```

**11520 字节/秒**的条件是连续发送、没有额外帧间间隔，只按 8N1 的帧开销计算。若应用层还有包头、长度、校验等字段，真正业务内容的吞吐量会更低。

| 容易混淆的数值 | 含义 |
| --- | --- |
| 115200 bit/s | 线路上所有位的速率 |
| 8 位 | 每帧中的有效数据位 |
| 10 位 | 8N1 一帧的总位数，包含起始位和停止位 |
| 11520 字节/秒 | 上述条件下，一秒可传的有效数据字节数 |

## 4. 没有单独时钟线，怎样知道何时采样

异步串口的两端各用自己的时钟，并提前配置匹配的波特率和帧格式。接收过程可以这样理解：

1. **等待并确认起始位**：线路空闲为高，出现下降沿后，接收硬件检查是否构成有效起始位。
2. **按位时间采样**：根据波特率确定每一位的时间，使用本地时钟在位的中间附近采样。
3. **按帧格式接收**：依次接收数据位、可选校验位和停止位，完成一帧的接收。

**起始位用于对齐开始时刻，波特率用于约定位时间，帧格式用于约定结构。**不能只设置相同波特率，却忽略数据位、校验位和停止位是否匹配。[RM0008：起始位检测与接收器][rm0008]

接收与采样由 USART 硬件完成。CPU 通常读取接收结果，不需要在软件中逐位读取 GPIO。

<details>
<summary>串口帧与应用层数据包有什么区别？</summary>

本文说的 8N1“一帧”，通常只承载一个数据字节；应用层数据包可以包含多个字节，例如：

```text
包头 | 长度 | 命令 | 数据内容 | 校验
```

包头、长度和校验怎样定义，是应用协议的约定。USART 硬件收到一个字节后，并不会因此知道整个业务数据包已经收齐。

程序需要把收到的字节保存下来，再按约定的长度、分隔符或其他规则识别完整数据包。

</details>

## 5. 轮询和中断怎样接收数据

以 **8 位接收、不使用 DMA**为例：

| 方式 | 怎样发现有数据 | CPU 接下来做什么 |
| --- | --- | --- |
| 轮询接收 | 程序主动检查接收就绪标志 | 就绪后读取数据，保存到缓冲区 |
| 中断接收 | 开启接收中断后，外设产生请求，CPU 在条件允许时响应 | 进入 ISR，确认来源，读取数据并保存 |

两种方式都依赖 USART 硬件完成按位接收。区别主要是 **CPU 主动检查状态，还是由中断机制通知 CPU 处理**。可联系 [中断与轮询](interrupts-nvic-exti.md) 理解。

### F103 的 RXNE、DR 和 RAM 缓冲区

| 名称 | 在哪里 | 作用 |
| --- | --- | --- |
| RXNE | `USART_SR` 状态寄存器中的标志位 | 表示接收数据已就绪，可以读取 |
| DR | `USART_DR` 数据寄存器 | CPU 从这里取出收到的数据 |
| 接收缓冲区 | 通常是 RAM 中的数组等存储空间 | 保存已经取出的字节，供后续处理 |

普通接收时，数据就绪后硬件置位 RXNE。若 `USART_CR1` 中的 `RXNEIE` 已使能，就能产生相应的接收中断请求；CPU 是否立即执行 ISR，还取决于 NVIC、屏蔽和优先级等条件。[RM0008：USART_SR 与 USART_CR1][rm0008]

```text
USART 硬件收到一个字节，数据就绪，RXNE 置位
    ├─ 轮询：CPU 检查到 RXNE
    └─ 中断：已使能的接收中断请求 → NVIC → CPU 响应
                           ↓
                  CPU 读取 USART_DR
                           ↓
                  保存到 RAM 接收缓冲区
                           ↓
                  按应用协议组包、处理
```

**读取 USART_DR 会清除 RXNE。**取走数据本身就是这类标志的正常处理方式，不应照搬 EXTI 挂起位“写 1 清除”的方法；错误标志等其他来源按各自规定处理。[RM0008：接收数据寄存器非空标志][rm0008]

### 接收一个字节，不等于收完一整包

你说的“接收完后产生中断通知 CPU”，对应这里的 RXNE 接收过程时，更准确是：**收到一个字节并就绪后，在相应通路已使能时产生请求。**

ISR 中通常及时取出数据、保存到缓冲区；完整包判断和耗时的业务处理可以放在主循环或任务中。

<details>
<summary>使用 HAL 时，“接收完成回调”一定是每字节调用一次吗？</summary>

不一定。以 `HAL_UART_Receive_IT` 为例，软件会跟踪你指定的接收数量，在这次数量完成时调用接收完成回调。若指定接收 1 字节，完成一次就是 1 字节；若指定多个字节，完成条件按这次接收请求的数量判断。

这类按指定数量发起的中断接收，在完成后会结束本次接收；若要继续使用该方式接收，需安排下一次接收请求。

底层 RXNE 接收事件与上层 API 的“接收完成回调”属于不同层次，不能直接等同。[ST 官方 F1 HAL UART 驱动][hal-uart]

</details>

## 6. 易错点

| 容易混淆的说法 | 准确理解 |
| --- | --- |
| 两块板 TX 接 TX、RX 接 RX | 普通接线是 TX 接对方 RX，并共地 |
| 115200 表示每秒 115200 字节 | 常见二进制 UART 中对应 115200 bit/s 的线路速率 |
| 8N1 总共 10 位，还要再加起始位 | 这 10 位已经包含 1 位起始位 |
| 接收端只要知道波特率，就能随时从任意位置读 | 还需要起始位对齐和匹配的帧格式 |
| 收到一字节就代表业务数据包完整 | 业务数据包需要程序按应用协议识别 |
| 开了中断，数据就会自动一直存进数组 | 普通中断接收仍需程序读取数据并保存 |
| RXNE 要用 EXTI 那样的写 1 方法清除 | F103 普通接收中，读取 DR 就会清除 RXNE |

## 7. 口述版本

> USART 支持同步和异步通信，本文使用异步模式。TX 发送、RX 接收，两块板交叉连接并共地。双方约定波特率和帧格式，接收端检测起始位，再按位时间采样。8N1 表示 8 位数据、无校验、1 位停止，加上 1 位起始，一帧共 10 位。115200 波特、连续 8N1 传输时，理论有效字节率为每秒 11520 字节。接收可以轮询 RXNE，也可以开启接收中断，及时读取 DR 并保存到 RAM；完整数据包还需要应用程序按协议判断。
