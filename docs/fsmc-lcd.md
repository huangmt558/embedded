# FSMC 与 LCD 驱动

[返回目录](../README.md)

**CPU 向映射地址写入数据，FSMC 把这次访问转换成外部总线信号，LCD 控制器再执行对应的命令或数据操作。**理解这条链路，就能把接线、地址和屏幕刷新联系起来。

本文针对带内部显示存储器、使用 8080 并行接口的常见 LCD 控制器，以及具备 FSMC 和相应引脚的 STM32。[ST AN2790：§2][an2790]

## 1. 先分清各部分的职责

FSMC 是灵活静态存储控制器，本来用于访问 SRAM、NOR Flash、NAND Flash 等外部存储器；其异步读写接口也可以配合兼容的 LCD 控制器。

| 部分 | 负责什么 |
| --- | --- |
| CPU／驱动代码 | 组织命令、参数和像素，发起访问 |
| FSMC | 按配置产生地址、片选、数据和读写控制信号 |
| LCD 控制器 | 解释命令、接收像素，并扫描内部显存 |
| LVGL | 绘制界面，将像素放入绘图缓冲区 |
| DMA | 在芯片和配置支持时搬运像素，减少 CPU 搬运负担 |

使用前应确认芯片与封装支持该外设。例如 **STM32F103C8T6 没有 FSMC**，不能直接套用本篇的 FSMC 接线与地址示例。[F103C8 数据手册][f103c8]

## 2. 接线怎样决定访问地址

常见的 8080 接口连接如下：

| FSMC 信号 | LCD 信号 | 用途 |
| --- | --- | --- |
| D0～Dn | D0～Dn | 传输命令、参数和像素 |
| NEx | CS | 片选 |
| NWE | WR | 写控制 |
| NOE | RD | 读控制 |
| 某根地址线 Ax | DC／RS | 选择命令或数据 |

复位、背光等信号另行控制。常见控制器用 DC／RS 的 `0` 选择命令、`1` 选择数据，具体以控制器手册为准。

**命令和数据都走数据线。**访问不同地址的作用，是改变接到 DC／RS 的那根地址线电平。

### 一个 16 位总线的例子

假设使用 **NE1 对应区域、16 位总线、A16 连接 DC／RS**，且 DC 为 `0` 表示命令：

```c
#include <stdint.h>

#define LCD_CMD_ADDR   0x60000000UL
#define LCD_DATA_ADDR  0x60020000UL

#define LCD_CMD   (*(volatile uint16_t *)LCD_CMD_ADDR)
#define LCD_DATA  (*(volatile uint16_t *)LCD_DATA_ADDR)
```

GPIO、FSMC 和屏幕控制器完成初始化后，可以这样访问：

```c
LCD_CMD  = command;  /* command 是待发送的命令值 */
LCD_DATA = data;     /* data 是参数或像素数据 */
```

`volatile` 用于要求编译器保留相应硬件访问。以上地址仅适用于这里假设的接线和配置；实际地址需要随片选、位宽和地址线调整。

<details>
<summary>为什么数据地址要加 0x20000？</summary>

CPU 按字节编址。16 位总线每次访问占 2 个字节，所以外部 FSMC 的 A0 对应 CPU 地址的 bit1，Ax 对应 bit(x + 1)。

```text
A16 → CPU 地址 bit17
偏移 = 1 << 17 = 0x20000
数据地址 = 0x60000000 + 0x20000 = 0x60020000
```

8 位总线下地址位的对应关系不同，不能照搬这个偏移。[ST AN2790：§2.2 的 NEx／Ax 地址示例][an2790]

</details>

## 3. 像素怎样显示到屏幕上

以写一个矩形区域为例：

```text
设置列范围 → 设置行范围 → 发送写显存命令 → 连续写入像素
```

具体命令值、参数格式和像素格式由 LCD 控制器决定。常见控制器会自动更新内部像素写入位置，因此 CPU 可以反复写入同一个 `LCD_DATA` 地址。

这次写入的链路是：

```text
CPU 写 LCD_DATA → FSMC 输出片选、DC 和写时序 → LCD 接收数据
```

<details>
<summary>为什么 8080 接口通常不需要持续提供像素时钟？</summary>

对本文讨论的带内部显存的控制器，MCU 通过读写脉冲把像素写入显存，后续由控制器自行扫描面板。

RGB 接口通常需要持续提供像素时钟与同步信号，接口工作方式不同，不能直接套用本文流程。

</details>

## 4. 与 LVGL、DMA 配合

```text
界面变化 → LVGL 渲染缓冲区 → 刷新回调
         → 驱动设置写入区域并发送像素 → 通知 LVGL 传输完成
```

**传输完成后，LVGL 才能复用对应缓冲区。**同步发送就在发送结束后通知；使用 DMA 等异步发送时，要在传输真正完成后通知。[LVGL 显示驱动文档][lvgl-display]

| 容易混在一起的工作 | 谁负责 |
| --- | --- |
| 提供 LVGL 时间基准 | 系统计时机制 |
| 执行动画、定时处理和刷新任务 | LVGL 的处理函数 |
| 产生 LCD 读写脉冲 | FSMC 的时钟、访问模式和时序配置 |

如果驱动用 CPU 循环写像素，CPU 仍参与每次写入；使用 FSMC 不会自动搬运整个缓冲区。DMA 可以在硬件支持时承担搬运，由 FSMC 继续负责外部总线时序。

## 5. 按需展开：时序配置与排查

<details>
<summary>配置时序时，需要关注哪些参数？</summary>

| 参数 | 主要用途 |
| --- | --- |
| 地址建立时间 | 为地址与选择信号提供建立时间 |
| 数据建立时间 | 配合访问模式确定数据阶段和读写脉冲时序 |
| 地址保持时间 | 在适用模式下保持地址 |
| 总线转换时间 | 为总线切换预留间隔 |

参数是否生效、如何从时钟周期换算成时间，要结合具体芯片参考手册、访问模式和 LCD 控制器的时序图判断。[ST AN2790：§2.6][an2790]

</details>

<details>
<summary>屏幕不亮、花屏或刷新慢时，先检查什么？</summary>

- **不亮或初始化失败**：先核对供电、复位、片选、命令／数据选择和初始化命令，再检查读写时序。
- **像素或颜色错误**：核对总线位宽、像素格式、发送顺序与时序裕量。
- **读回异常**：检查读控制信号、数据方向、读取格式和读时序。
- **刷新过慢**：检查时序是否过于保守，以及 CPU 是否在逐像素搬运，评估 DMA 的可用性。

这些是排查方向。具体建立、保持时间和数据采样边沿，仍要满足实际控制器手册的要求。

</details>

## 6. 易错点

| 容易混淆 | 正确理解 |
| --- | --- |
| FSMC 只能读取外部存储器 | 它也能写入 |
| 异步接口就一定能连接 | 还要核对电平、位宽和时序 |
| FSMC 会自动理解 LCD 命令 | 命令及参数顺序由驱动代码组织 |
| 每个像素都对应一个 CPU 地址 | 常见做法是反复写固定数据地址，LCD 内部推进位置 |
| 使用 FSMC 后 CPU 就不用搬运像素 | CPU 循环写入时仍参与，DMA 才能在支持时辅助搬运 |
| SysTick 决定 LCD 写脉冲宽度 | 写脉冲由 FSMC 的配置与时钟决定 |
| 8 位与 16 位总线使用相同地址偏移 | 外部地址线与 CPU 地址位的关系不同 |

## 7. 口述版本

FSMC 本来用于访问外部存储器。配置合适的信号连接和异步读写时序后，也可以驱动使用 8080 接口的 LCD 控制器。

程序通过不同映射地址选择命令或数据接口，先设置屏幕写入区域，再连续写入像素。FSMC 负责产生外部读写信号；LVGL 负责绘制界面，显示驱动负责把像素发给屏幕，并在传输完成后通知 LVGL。
