# I²C 通信协议

[返回目录](../README.md)

I²C 读写最容易混淆的是三件事：**器件地址选谁、寄存器地址选哪里、当前由谁应答。**先把这三件事分清，再看总线时序。

本文讨论常见的 7 位地址、双向 I²C 通信；使用“主机／从机”称呼，分别对应规范中的 controller／target。[规范：§3.1][i2c-spec]

## 1. 核心概念

I²C 是使用 **SDA 数据线和 SCL 时钟线**的同步串行通信协议，支持多主多从，常见通信方式为半双工。

| 要点 | 含义 |
| --- | --- |
| 器件地址／从机地址 | 选择总线上的器件 |
| 寄存器地址 | 选择器件内部要访问的位置，格式由器件规定 |
| 地址后的读写位 | `0` 为写，`1` 为读，方向以主机为参照 |
| 数据字节 | 8 位，高位先发送 |
| 第 9 个时钟 | 用于 ACK／NACK；时钟由主机产生 |

**谁接收字节，谁负责应答。**发送方在应答阶段释放 SDA；接收方拉低 SDA 表示 ACK，释放 SDA、让它保持高电平表示 NACK。

## 2. 常用寄存器读写

以下流程以“一个寄存器地址字节”为例。寄存器地址长度、连续访问方式和地址自动递增能力，都要查具体器件手册。

### 写寄存器

```text
START → 器件地址+写位 → ACK → 寄存器地址 → ACK
      → 数据 → ACK → STOP
```

主机发送地址和数据，从机应答。连续写入时，重复“数据 → ACK”，正常写完由主机发送 STOP。

### 读寄存器

```text
START → 器件地址+写位 → ACK → 寄存器地址 → ACK
      → 重复起始 → 器件地址+读位 → ACK
      → 数据 → 主机 NACK → STOP
```

前半段写操作用于指定“接下来读哪个寄存器”；重复起始保持这次组合访问的连续性，再切换到读方向。

从机发送数据时，主机负责应答：**还要继续读就 ACK，最后一个字节读完就 NACK，再 STOP。**

## 3. 时序怎么判断

| 阶段 | SDA 与 SCL 的关系 |
| --- | --- |
| START | SCL 为高时，SDA 从高变低 |
| STOP | SCL 为高时，SDA 从低变高 |
| 数据位 | SDA 在 SCL 低电平期间改变，高电平期间保持稳定 |
| ACK／NACK | 第 9 个时钟高电平期间读取 SDA：低为 ACK，高为 NACK |
| 重复起始 | 不先发送 STOP，直接再次产生 START |

这些是常用时序的判断方法；实际实现还需满足建立时间、保持时间及上升时间要求。[规范：§3.1.3～§3.1.6、§6][i2c-spec]

## 4. 按需展开：电气与总线机制

<details>
<summary>为什么使用开漏输出和上拉电阻？</summary>

常见 I²C 总线采用开漏输出与上拉电阻：发送 `0` 时主动拉低，发送 `1` 时释放信号线，由上拉电阻拉高。

只要有一个器件拉低，总线就保持低电平，形成“线与”。这样既能避免多个输出主动拉高、拉低产生冲突，也为仲裁和时钟拉伸提供了基础。

上拉电阻与总线电容共同影响上升时间，因此上拉阻值需要结合总线速度、电容和器件的灌电流能力选择。

</details>

<details>
<summary>多主机同时发送时，谁继续通信？</summary>

主机边发送边读取 SDA。双方发送相同位时继续；遇到第一个不同位时，发送 `1` 却读到 `0` 的主机仲裁失败，停止竞争。

```text
发送顺序 → 高位在前

主机 A：1  0  1 …
主机 B：1  0  0 …
总线  ：1  0  0 …
             ↑
       A 发送 1，却读到 0，A 失败
```

地址格式相同、地址不同的主机同时竞争时，访问较小地址的一方会先胜出；地址相同时，仲裁还可能延续到读写位或数据。如果发送内容一直相同，就可能无法分出胜负。

仲裁发生在同时竞争的主机之间。总线已经被占用时，其他主机要等待，不能因为地址小就抢占。[规范：§3.1.8][i2c-spec]

</details>

<details>
<summary>什么是时钟拉伸？</summary>

主机释放 SCL、准备让它变高时，支持时钟拉伸的从机可以继续将 SCL 拉低，暂停传输；准备好后再释放，通信继续。

支持这种机制的主机必须读取 SCL 的实际电平，确认它真的变高。仅把 GPIO 设置为“释放”，还不能说明总线已变高。

时钟拉伸是可选能力，是否支持取决于具体器件和主机实现。[规范：§3.1.9][i2c-spec]

</details>

<details>
<summary>软件 I²C 和硬件 I²C 有什么区别？</summary>

软件 I²C 由程序控制 GPIO 产生时序；硬件 I²C 使用 MCU 的 I²C 外设完成主要时序。

两者遵循相同的协议，但是否支持仲裁、时钟拉伸等能力，需要检查具体实现。

</details>

## 5. 易错点

| 容易混淆 | 正确理解 |
| --- | --- |
| 把器件地址当成寄存器地址 | 前者选器件，后者选内部位置 |
| 收到 ACK 就表示内部操作全部完成 | ACK 是应答，器件内部写入等操作可能仍需要时间 |
| 写完由主机补一个 NACK | 常见正常写入以从机 ACK、主机 STOP 结束 |
| 读到最后一个字节仍然 ACK | 主机应 NACK，表示结束本次读取，再发 STOP |
| 在第 9 个应答时钟内产生重复起始 | 第 9 个时钟完成应答，重复起始另行产生 |
| 连续读写一定自动递增寄存器地址 | 由器件协议决定 |

## 6. 口述版本

I²C 使用 SDA 和 SCL 两根线进行同步串行通信。主机先发送器件地址和读写位；每个字节有 8 位，后面用第 9 个时钟应答，谁接收字节谁应答。

常见寄存器读取先用写操作指定寄存器地址，再通过重复起始切换到读方向。读取期间由主机应答，最后一个字节读完发送 NACK，再发送 STOP。
