# 中断、轮询与 NVIC／EXTI

[返回目录](../README.md)

**中断是在满足响应条件时转入处理函数的机制；轮询是程序主动反复检查条件的方式。**“清除中断”则需要说明清的是哪一层的标志，不能与屏蔽中断、退出中断混为一谈。

本文以 **STM32F103／Cortex-M3 的普通可配置外设中断**为主。

## 1. 什么是中断，什么是轮询

**中断（Interrupt）**：外设或软件产生中断请求。当使能、屏蔽和优先级等条件允许时，CPU 暂时转离当前执行流程，保存必要现场，进入对应的中断服务函数（ISR）；正常返回时恢复被打断的执行。

**轮询（Polling）**：程序主动读取输入或状态标志，检查条件是否满足；满足就处理，不满足就继续等待或执行其他工作，之后再检查。

| 比较 | 中断 | 轮询 |
| --- | --- | --- |
| 怎样发现需要处理 | 请求到达后，由中断机制决定是否响应 | 程序主动检查条件 |
| 处理代码在哪里执行 | 中断服务函数中 | 正常程序流程中 |
| 是否一定立即处理 | 还取决于使能、屏蔽和优先级 | 取决于下一次检查何时发生 |
| CPU 开销 | 有进入、退出及处理开销 | 有反复检查开销 |

轮询可以是循环中连续查询的“忙等”，也可以是主循环或定时任务中的周期性检查。中断和轮询也能配合使用，例如中断记录事件、主循环处理业务。

## 2. EXTI、NVIC 和向量表分别做什么

| 部分 | 主要职责 |
| --- | --- |
| EXTI | 外部中断／事件控制器，对配置的信号检测触发条件，产生请求 |
| NVIC | 管理中断使能、挂起、活动状态与优先级，参与决定响应和抢占 |
| 向量表 | 保存异常和中断处理函数的入口地址 |

**处理函数入口地址在向量表里，优先级在相关优先级寄存器里。**NVIC 不存放处理函数的程序代码。[Arm NVIC 说明][nvic]

### 按键与串口走不同的请求路径

```text
按键：GPIO 边沿 → EXTI → NVIC → CPU 执行 EXTI 中断函数
串口：USART 接收就绪 → USART 中断请求 → NVIC → CPU 执行 USART 中断函数
```

F103 的 GPIO 外部中断支持上升沿、下降沿或双边沿触发。串口的接收引脚也有电平变化，但 USART 自己完成采样和数据接收，接收就绪中断通常不经过 EXTI。以接收就绪为例，USART 置位 RXNE，并在 RXNEIE 已使能时产生相应请求。

以上都以相应中断通路已使能、且 CPU 满足响应条件为前提。[RM0008：EXTI 与 USART][rm0008]

<details>
<summary>“发生了一件事”和“EXTI 事件模式”有什么区别？</summary>

“串口收到数据”“定时器溢出”是泛指外设发生了某种事件，不代表它们都要进入 EXTI。

EXTI 的事件模式则是专门的硬件通路：事件输出可以用于唤醒等待事件的 CPU，例如配合 WFE。单独启用事件模式，不会因为这条事件输出而经 NVIC 执行 ISR。

同一 EXTI 线路可以分别启用中断路径和事件路径。如果两条路径都开启，就可能同时产生相应中断请求和事件。[PM0056：外部事件输入][pm0056]

</details>

## 3. 一次中断怎样进入和退出

```text
事件发生，中断请求挂起
    ↓
满足使能、屏蔽和优先级等响应条件
    ↓
硬件保存必要现场，同时从向量表取得处理函数入口
    ↓
执行 ISR：确认来源，读取数据或处理事件，并按规定处理标志
    ↓
通过异常返回机制恢复现场，继续被打断的执行
```

**中断先产生请求，响应时才保存现场。**不是预先保存现场，再等待事件发生。[PM0056：§2.3.7][pm0056]

<details>
<summary>压栈保存哪些内容？处理完一定马上回到主程序吗？</summary>

F103 的 Cortex-M3 硬件会自动把 `R0～R3、R12、LR、PC、xPSR` 保存到当前使用的栈中。其他必须保留的寄存器，由编译器生成的代码按需保存。

若没有其他需要立即响应的异常或中断，正常异常返回会出栈恢复原执行现场。有满足条件的挂起中断时，可能通过“尾链”转入下一个 ISR，省去一次出栈和再次压栈。

栈帧仍保存在 RAM 中，可以联系 [启动流程和栈空间](stm32-startup-memory.md) 理解。复位启动本身不执行普通中断的这套现场压栈过程。

</details>

## 4. F103 的优先级怎样分组

F103 实现了 **4 个有效中断优先级位**。分组决定这 4 位中，多少位用于抢占优先级、多少位用于子优先级。[F1 分组定义][priority-groups]

- **抢占优先级**：决定能否打断正在执行的另一个中断。
- **子优先级**：抢占优先级相同时，决定多个挂起中断的处理先后，不能用于抢占。
- 对这些可配置优先级，**数值越小，优先级越高**。

<details>
<summary>展开分组表与一个例子</summary>

以下按 ST 库中的常用分组名称列出：

| 分组 | 抢占优先级位数 | 子优先级位数 |
| --- | ---: | ---: |
| Group 0 | 0 | 4 |
| Group 1 | 1 | 3 |
| Group 2 | 2 | 2 |
| Group 3 | 3 | 1 |
| Group 4 | 4 | 0 |

例如 Group 2 的两个字段各占 2 位，各自可取 `0～3`。

若 A、B 的抢占优先级相同，B 的子优先级更高，B 也不能打断正在执行的 A；当两者都挂起、需要选择下一个响应对象时，子优先级才参与比较。

优先级分组是全局设置。标准库的 `NVIC_PriorityGroup_x` 与 HAL 的 `NVIC_PRIORITYGROUP_x` 都是库命名，不应把名称后缀直接当作 AIRCR 中 PRIGROUP 字段的原始编码。[分组和抢占规则][pm0056]

</details>

## 5. “清除中断”到底指什么

日常说的“清除中断”不够精确。编写程序时，应该明确是**确认并清除中断源的状态标志**，还是**清除 NVIC 记录的挂起状态**。

| 操作 | 实际含义 |
| --- | --- |
| 清除中断源标志 | 按外设规定处理状态，例如清 EXTI_PR、读取接收数据 |
| 清除 NVIC 挂起位 | 清理 NVIC 记录的待响应状态，不等于清掉外设标志 |
| 屏蔽／禁用中断 | 暂时阻止相应响应，不保证标志和挂起状态被清除 |
| 退出 ISR | 结束本次中断处理，按异常返回机制继续执行 |

### F103 的两个具体例子

- **EXTI**：相应边沿发生后，`EXTI_PR` 对应位被置 1；向该位**写 1**可以把它清为 0。
- **USART 接收**：普通接收处理中，读取 `USART_DR` 取走数据，会清除 `RXNE` 标志。其他标志可能要求特定的读写顺序。

因此，不能统一规定“进入 ISR 后第一步一定清标志”。应先确认来源，再按手册要求处理数据、状态和清除顺序。[RM0008：EXTI_PR、USART_SR][rm0008]

<details>
<summary>为什么 EXTI 写 1 是清除？为什么不能只清 NVIC 挂起位？</summary>

“写 1 清除”是该寄存器定义的硬件操作语义：读取到 1 表示请求发生过，写入 1 则命令硬件清除该位，没有新触发时，之后读回的是 0。

例如，确认 EXTI0 有待处理请求后，寄存器操作片段可以写为：

```c
EXTI->PR = (1U << 0);  /* 只对 EXTI0 发出写 1 清除操作 */
```

对这种寄存器，使用定向写入可以避免读改写时把其他已经为 1 的挂起位也一起清掉。

内核接受普通中断请求时，通常会自动把这次请求从挂起转换为活动状态；不需要在每个 ISR 入口统一手动清 NVIC 挂起位。外设的源标志仍需按自己的机制处理。

`NVIC_ClearPendingIRQ()` 针对的是 NVIC 的挂起状态。外设请求仍然有效时，单清 NVIC 挂起位可能无效，或随后再次挂起。应处理实际中断源，不能把 NVIC 清挂起接口当作通用外设清标志接口。[PM0056：中断挂起行为][pm0056]

</details>

## 6. 按键为什么会反复进入中断

常见原因需要分开判断：

- **机械抖动**：一次按下或释放产生多个边沿，形成多次请求，需要消抖。
- **中断源未正确清除**：原来的请求仍然有效，需要检查状态和清除操作。

对于配置为边沿触发的 GPIO，稳定地保持高电平或低电平，本身不会不断产生新的边沿。

常见做法是在 ISR 中确认来源、按规定清标志并记录事件，把消抖确认和耗时业务放到主循环或定时处理里。清标志与消抖解决的是不同问题。

## 7. 易错点与口述版本

| 容易混淆 | 正确理解 |
| --- | --- |
| 轮询一定是一直卡在死循环里 | 也可以周期性查询 |
| 有请求就一定立即执行 ISR | 还取决于使能、屏蔽和优先级 |
| 所有中断都经过 EXTI | USART 等外设有自己的请求通路 |
| 向量表保存优先级 | 它保存处理函数入口地址 |
| 子优先级高就能抢占 | 抢占取决于抢占优先级 |
| 清除中断就是把所有标志写 0 | 清除方法由具体寄存器规定 |
| 进入 ISR 会自动清除全部外设标志 | NVIC 状态转换与外设标志清除要区分 |
| 中断处理函数里清标志就完成了按键消抖 | 清标志和消抖是两件事 |

口述时可以这样说：

中断是事件产生请求后，CPU 在满足响应条件时保存现场、进入中断服务函数，并在正常返回时恢复执行的机制。轮询则是程序主动反复读取状态、检查条件并处理。

F103 中，EXTI 负责外部中断或事件的触发，NVIC 管理中断响应与优先级，向量表保存处理函数入口。清除中断需要指明清哪一层标志，并按外设手册完成相应操作，不能把它与禁用中断或退出 ISR 混为一谈。
