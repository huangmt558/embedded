# 看门狗 IWDG 与 WWDG

## 一段话讲清楚

看门狗是用来帮助单片机从程序卡死等异常中恢复的硬件计数器：程序正常运行时，要在规定时间内“喂狗”，也就是重新装载计数器；如果没有按要求喂狗，看门狗就会触发复位，单片机重新走启动流程。STM32F103 的独立看门狗 IWDG 使用独立的 LSI 时钟，主要检查是否超时；窗口看门狗 WWDG 要求在指定时间窗口内喂狗，过早或过晚都可能触发复位。喂狗前应确认需要监控的任务确实正常运行，否则看门狗可能发现不了故障。

## 1. 喂狗和超时

以配置为约 1 秒超时的独立看门狗为例：

- 程序每 0.5 秒喂一次狗：正常情况下不会超时复位。
- 刚喂狗后程序卡死：大约再过 1 秒复位。
- 喂狗后 0.8 秒程序卡死：大约再过 0.2 秒复位。

每次喂狗都重新装载计数器；喂狗后程序继续执行，不需要等待复位。上面是便于理解的示例，实际超时时间受看门狗时钟误差等影响。

## 2. 两种看门狗

| 对比 | 独立看门狗 IWDG | 窗口看门狗 WWDG |
| --- | --- | --- |
| 时钟 | 独立的 LSI 内部低速时钟 | 来自 APB1 时钟 |
| 喂狗要求 | 超时前喂狗，F103 无过早喂狗限制 | 在规定窗口内喂狗，过早或超时会复位 |
| 用途 | 检查程序是否长时间没有正常运行；主时钟异常时仍有机会工作 | 还可以检查喂狗过早等时间异常 |

## 3. 怎么喂狗才有意义

不要只在定时器中断中无条件喂狗：主循环即使卡死，中断仍可能运行并继续喂狗。同样，如果只由任务 A 喂狗，任务 B 卡死也可能发现不了。

多个重要任务可以分别报告自己的运行状态，由统一的监控逻辑检查它们是否在规定时间内正常完成关键工作；确认通过后再喂狗。具体检查周期和超时时间应结合任务的最长执行时间设计。

## 4. 复位与初始化

看门狗超时后，单片机重新走启动流程并进入 main，不会从卡死的位置接着执行。如果故障每次启动都会发生，设备可能反复重启。

启动阶段也要考虑看门狗：例如看门狗已启动且 1 秒超时，而初始化需要 3 秒且期间没有喂狗，初始化可能一直无法完成。可根据实际耗时选择合适的超时时间，或在确认初始化正常推进时适当喂狗。

## 易错点

- 喂狗是重新装载计数器，不是触发复位。
- IWDG 主要看是否超时；WWDG 还限制喂狗过早。
- 看门狗只能发现会影响所设计的喂狗条件的故障，不能保证发现所有异常，也不能自动修复故障。
- IWDG 使用独立时钟，不代表它能在任何硬件故障下工作。

## 口述版本

看门狗是一个用于故障恢复的硬件计数器，程序正常时要按要求定期喂狗，程序卡死导致超时后看门狗会复位单片机。STM32F103 的 IWDG 使用独立低速时钟，WWDG 则要求在指定时间窗口内喂狗，过早或过晚都可能复位。实际使用时要检查关键任务是否正常运行，避免程序部分卡死但其他地方仍在喂狗。
