# DMA 串口接收

[返回目录](../README.md)

**USART 负责接收，DMA 负责搬运，CPU 负责配置 DMA 和处理数据。**循环接收时，程序记录下一个待处理位置，并及时处理未读数据。

本文以 **STM32F103、USART 异步 8 位接收、DMA 外设到内存、每次搬运 1 字节**为例。可先回顾 [USART 异步串口](usart-uart.md) 中的 RXNE、DR 和接收缓冲区。

## 1. DMA 怎样接收串口数据

DMA 是直接存储器访问控制器。配置好后，外设提出 DMA 请求，DMA 按配置完成数据搬运，CPU 不需要逐字节读取和写入 RAM。

```text
串口收到一个字节
        ↓
USART 数据就绪并提出 DMA 请求
        ↓
DMA 读取 USART_DR
        ↓
DMA 把字节写入 RAM 接收缓冲区
        ↓
CPU 在需要时处理缓冲区数据
```

CPU 仍需提前配置源地址、目标地址、数量和模式，也需要处理收到的数据。DMA 传输完成或半传输中断可按需要使能。[RM0008：USART 使用 DMA 接收][rm0008]

### 地址为什么一个固定、一个递增

例如，配置 DMA 将 4 个字节存入 `rx_buf[4]`：

| 地址 | 配置 | 原因 |
| --- | --- | --- |
| 外设地址：`USART_DR` | 不递增 | 每次都从同一个数据寄存器读取，新字节会更新寄存器内容 |
| 内存地址：`rx_buf` | 递增 | 按顺序写入 `rx_buf[0]`、`rx_buf[1]` 等不同位置 |

在本例的 8 位接收配置下，每次搬运 1 字节。寄存器里的**数据**会变化，寄存器的**地址**保持不变。[RM0008：DMA 地址配置][rm0008]

## 2. 普通模式：配置多少，就搬多少

假设配置接收 10 字节，对方暂时只发了 3 字节：

```text
配置总量：10 字节
已搬运：   3 字节
剩余数量： 7 字节
```

这 3 字节已经在 RAM 中，但还没有达到 10 字节的**传输完成条件**。普通模式到达配置数量后停止响应新的 DMA 请求；如需下一次接收，需要重新准备并启动。[RM0008：DMA 普通模式][rm0008]

如果已知每次接收固定长度，普通模式容易理解。长度不固定时，可以结合串口 **IDLE 空闲检测**，在发生空闲事件时检查已收到多少数据。

<details>
<summary>普通模式结合 IDLE，怎样处理已收到的数据？</summary>

一种常见思路是：检测 IDLE 后暂停 DMA，读取剩余数量并计算收到的数量，处理或复制数据，然后按需要重新配置并启动接收。

```text
已接收数量 = 配置的总数量 - DMA 剩余数量
          = 10 - 7 = 3 字节
```

停止 DMA、处理和重新启动之间存在接收空窗；如果对方继续发送，数据可能来不及搬走。操作顺序还应结合所用库和芯片的状态清除规则设计。

F103 的 IDLE 标志按手册规定通过**先读取 USART_SR，再读取 USART_DR**的顺序清除。与正在接收的 DMA 配合时，要考虑对 DR 的访问时序，具体以参考手册和使用的库实现为准。[RM0008：USART_SR 的 IDLE 标志][rm0008]

</details>

## 3. 循环模式：写到末尾再回到开头

循环模式可以让 DMA 持续接收，减少反复关闭和开启 DMA 造成的接收空窗。

以 4 字节缓冲区为例：

```text
rx_buf[0] → rx_buf[1] → rx_buf[2] → rx_buf[3]
    ↑                                      ↓
    └────────── 写满后回到开头 ─────────────┘
```

DMA 写完最后一个位置后，会自动重新装载传输数量和地址，继续响应请求。如果 `rx_buf[0]` 的旧数据尚未处理，下次写入时它就会被覆盖。[RM0008：DMA 循环模式][rm0008]

**记录位置并及时处理数据即可，不需要每次把整个数组清零。**DMA 正在写缓冲区时，程序应避免清零操作覆盖正在接收的新数据。

### 读位置与写位置

- **读位置**：程序下一个要处理的字节所在位置。
- **写位置**：DMA 下一个要写入的位置。

DMA 保持运行时，程序可以在 IDLE 等事件到来后读取剩余计数的快照，确定当前写位置，再和读位置比较，找出新增数据。

在本篇“每次搬运 1 字节”的例子里，可以用下面的关系理解写位置：

```text
写位置 = (缓冲区大小 - DMA 剩余数量) % 缓冲区大小
```

处理完新增数据后，程序更新读位置。DMA 可能同时继续写入，数据需要及时处理或复制，避免被回绕覆盖。

### 回绕怎么计算

缓冲区大小为 10，下标为 `0～9`。如果**下一个待处理位置**为 7，DMA **下一个写入位置**为 2，且期间只回绕一次、没有漏掉整圈：

```text
新数据：7 → 8 → 9 → 0 → 1
下一个写入位置：2（不算在本次新数据里）

数量 = (10 - 7) + 2 = 5 字节
```

<details>
<summary>再看两个回绕例子</summary>

以下都以长度 10、下标 `0～9` 为例，起点表示**下一个待处理位置**，终点表示 **DMA 下一个写入位置**：

| 起点 | 终点 | 新数据下标 | 数量 |
| ---: | ---: | --- | ---: |
| 8 | 1 | 8、9、0 | 3 |
| 9 | 1 | 9、0 | 2 |

终点是下一个要写的位置，**不计入这次已收到的数据**。

</details>

### 两次位置相同，不一定是没有新数据

缓冲区大小为 10，两次查看时写位置都是 1，期间可能：

- 没有收到新数据。
- 收到 10 字节，DMA 回绕一圈，位置又回到 1。
- 收到 20 字节，DMA 回绕两圈，位置仍是 1。

因此，**只看两个位置或剩余计数，无法判断中间是否漏掉整圈数据**。如果软件没有及时取走旧数据，就可能已经发生覆盖。

## 4. IDLE、半传输和传输完成事件

| 事件 | 什么情况下帮助程序处理 |
| --- | --- |
| USART IDLE | 线路出现空闲，提醒程序检查当前已收到的数据 |
| DMA 半传输 HT | DMA 已搬到配置缓冲区的一半 |
| DMA 传输完成 TC | DMA 已搬完本轮缓冲区 |

以 10 字节循环缓冲区为例，启用相应中断后：

```text
写完 rx_buf[0～4] → 半传输中断，可处理前半区
写完 rx_buf[5～9] → 传输完成中断，可处理后半区
DMA 回到 rx_buf[0]，继续接收
```

DMA 的传输完成表示**本轮缓冲区写满**，不等于应用层完整数据包一定收齐。IDLE 也只说明线路出现空闲，不自动保证业务包完整；仍需根据长度、分隔符、校验等应用协议判断。

连续发送时可能长时间没有 IDLE，因此可以结合 HT／TC 及时处理。[RM0008：DMA 半传输与完成标志][rm0008]

<details>
<summary>多个事件都要处理数据，怎样避免重复或漏处理？</summary>

可以由统一的处理逻辑跟踪**同一个读位置**：每次收到 IDLE、HT 或 TC 通知时，读取写位置快照，处理尚未消费的部分，再更新读位置。不同中断或任务可能同时访问该位置时，还需要安排好同步。

这不是无限防丢保证：DMA 仍在写入，软件必须在数据被覆盖前处理或复制；中断若长时间被屏蔽或处理不及时，同一标志的多次事件也未必能逐次计数。缓冲区大小、处理速度和发送速率需要一起考虑。

</details>

## 5. 缓冲区变大，为什么仍可能丢数据

增大缓冲区、分成两个半区、使用双缓冲或环形缓冲区，都可以更好地应对短时突发并安排读写。

但如果**长期平均接收速度高于处理速度**，积压会持续增长，有限缓冲区最终仍会满。

例如每秒收到 1000 字节，只能处理 800 字节：

```text
每秒积压 = 1000 - 800 = 200 字节
空缓冲区容量 = 1000 字节
理论积满时间 ≈ 1000 / 200 = 5 秒
```

还需要根据系统情况提高处理速度、降低发送速度或使用合适的流控；更大的缓冲区提供的是吸收突发和处理延迟的空间。

## 6. 易错点

| 容易混淆的说法 | 准确理解 |
| --- | --- |
| DMA 接收时，CPU 每个字节仍要读 DR 写数组 | DMA 按外设请求搬运，CPU 负责配置和后续处理 |
| 串口 DR 和数组地址都要递增 | 本例 DR 地址固定，数组写入地址递增 |
| 普通模式配 10 字节，收 3 字节就会传输完成 | 还剩 7 字节，未达到本次 DMA 完成条件 |
| IDLE 一定表示完整业务包结束 | IDLE 提示线路空闲，业务包仍按协议判断 |
| 循环 DMA 每次 IDLE 都必须关闭 | 可以保持 DMA 运行，按位置跟踪并处理新数据 |
| 两次写位置一样，一定没有收到数据 | 也可能绕过一圈或多圈 |
| 开 HT 和 TC 中断就绝对不会丢数据 | 仍依赖及时响应、处理速度和足够缓冲 |
| 每处理一次，都要把整个缓冲区清零 | 跟踪读位置并及时处理，同时留意回绕和覆盖 |

## 7. 口述版本

> 串口 DMA 接收时，USART 收到字节后向 DMA 提出请求，DMA 从固定的 USART_DR 地址读取数据，按配置写入 RAM 中递增的缓冲区地址。普通模式按设定数量搬运，循环模式写到末尾后自动回到开头。处理循环缓冲区时，要记录下一个待处理位置，并根据 DMA 剩余数量取得写位置，注意回绕和覆盖。IDLE、半传输和传输完成事件可以辅助及时处理；业务包仍按协议判断，处理速度长期跟不上接收速度时，有限缓冲区最终会满。
