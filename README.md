# 嵌入式知识点总结

## 一、I²C 通信协议

### 1. 基本概念

I²C 是一种支持多主多从的半双工同步串行通信协议，使用两根信号线：

| 信号线 | 作用 |
| --- | --- |
| SDA | 传输地址、数据和应答 |
| SCL | 提供时钟，通常由主机产生 |

基本特点：

- 每个字节为 **8 位，高位先发送**。
- 常见的从机地址为 **7 位**，后面加 **1 位读写位**。
- 读写位为 `0` 表示写，为 `1` 表示读。
- **从机地址**：决定访问哪个器件。
- **寄存器地址**：决定访问器件内部哪个位置。

### 2. 为什么使用开漏输出

SDA 和 SCL 通常采用 **开漏输出 + 上拉电阻**。

| 发送内容 | 引脚动作 |
| --- | --- |
| 发送 `0` | 主动拉低信号线 |
| 发送 `1` | 释放信号线，由上拉电阻拉高 |

只要有一个器件拉低，总线就是低电平，形成“线与”。

采用这种方式有三个主要作用：

1. 避免多个器件共用总线时，一个主动拉高、另一个主动拉低造成电气冲突。
2. 支持多主机仲裁。
3. 支持时钟拉伸。

> 上拉电阻和总线电容会影响信号上升速度。

### 3. 基本时序

| 信号 | 时序 |
| --- | --- |
| 起始信号 START | SCL 为高电平时，SDA 由高变低 |
| 终止信号 STOP | SCL 为高电平时，SDA 由低变高 |
| 数据传输 | SDA 在 SCL 低电平期间改变，高电平期间保持稳定 |
| ACK | 第 9 个时钟，接收方拉低 SDA |
| NACK | 第 9 个时钟，接收方释放 SDA，使其保持高电平 |
| 重复起始 Sr | 不先发送 STOP，直接再次产生 START |

#### 应答规则

每传完 8 位数据，第 9 个时钟用于应答：

- 发送方释放 SDA。
- 接收方在第 9 个时钟的高电平到来前准备好应答电平。
- 在第 9 个时钟的高电平期间，应答电平保持稳定。
- 发送方在此期间读取 SDA，判断 ACK 或 NACK。

> **谁接收字节，谁负责应答。**
>
> 重复起始不是在第 9 个应答时钟内产生的。

### 4. 写寄存器的过程

首先主机发送起始信号，再发送从机地址加写位，从机应答 ACK。

然后主机发送要写的寄存器地址，从机再应答 ACK。

接着主机发送数据，每发送一个字节，都由从机应答 ACK。如果还有数据，主机就继续发送；如果写完了，主机直接发送终止信号。

#### 时序流程

```text
主机发送 START
    ↓
主机发送从机地址 + 写位 0
    ↓
从机应答 ACK
    ↓
主机发送寄存器地址
    ↓
从机应答 ACK
    ↓
主机发送数据 1
    ↓
从机应答 ACK
    ↓
主机发送数据 2（如果需要继续写）
    ↓
从机应答 ACK
    ↓
主机发送 STOP
```

#### 注意事项

- 写数据时，**主机发送，从机接收并应答**。
- 正常写完，主机直接发送 STOP，**不需要主机发送 NACK**。
- 如果从机无法接收，可能回复 NACK，主机应根据情况结束通信或重试。

### 5. 读寄存器的过程

首先主机发送起始信号，再发送从机地址加写位，从机应答 ACK。

然后主机发送要读取的寄存器地址，从机应答 ACK。

接着主机发送重复起始信号，再发送从机地址加读位，从机应答 ACK。

然后从机开始发送数据。主机每接收一个字节，如果还想继续读取，就应答 ACK；如果已经读到最后一个字节，就发送 NACK，再发送终止信号。

#### 时序流程

```text
主机发送 START
    ↓
主机发送从机地址 + 写位 0
    ↓
从机应答 ACK
    ↓
主机发送要读取的寄存器地址
    ↓
从机应答 ACK
    ↓
主机发送重复起始 Sr
    ↓
主机发送从机地址 + 读位 1
    ↓
从机应答 ACK
    ↓
从机发送数据 1
    ↓
主机应答 ACK（继续读取）
    ↓
从机发送数据 2
    ↓
主机应答 NACK（最后一个字节）
    ↓
主机发送 STOP
```

#### 为什么先写再读

前面的写操作，是为了告诉从机：

> 接下来要读取哪个寄存器。

后面通过重复起始，切换为读操作。

> 这是常见的寄存器读取流程，具体操作由器件数据手册规定。

### 6. 多主机仲裁

多个主机同时开始通信时，会 **边发送、边读取 SDA**。

仲裁规则：

1. 双方发送的位相同，就继续发送。
2. 遇到第一个不同的位，发送 `0` 的主机继续。
3. 发送 `1` 却读到 `0` 的主机仲裁失败，停止竞争并释放 SDA。

#### 举例

```text
发送顺序：从左到右

主机 A：1  0  1 …
主机 B：1  0  0 …
总线  ：1  0  0 …
              ↑
      A 想发 1，却读到 0
      A 仲裁失败，B 继续
```

并不是提前规定谁发送 `0`、谁发送 `1`，而是由各自准备发送的地址或数据决定。

#### 地址和优先级的关系

在同时竞争、地址格式相同且地址不同的情况下：

- 访问较小从机地址的主机会获胜。
- 如果地址相同，还可能继续在读写位或后续数据中分出胜负。
- 如果发送的内容一直相同，就可能一直无法分出胜负。

> **地址小不能抢占已经开始的通信。**
>
> 总线已经被占用时，其他主机必须等待。

### 7. 时钟拉伸

主机释放 SCL，准备让它变高时，支持时钟拉伸的从机可以继续拉低 SCL，让主机等待。

等从机准备好后，再释放 SCL，通信继续。

```text
主机释放 SCL
    ↓
从机还没准备好，继续拉低 SCL
    ↓
主机检测到 SCL 仍为低，等待
    ↓
从机准备好，释放 SCL
    ↓
SCL 被上拉为高，通信继续
```

> 支持时钟拉伸的主机，需要读取 SCL 的实际电平，不能只根据自己的输出动作判断时钟已经变高。

### 8. 易错点总结

| 易错点 | 正确理解 |
| --- | --- |
| 从机地址和寄存器地址混淆 | 从机地址选器件，寄存器地址选器件内部的位置 |
| ACK 就代表全部操作完成 | ACK 表示接收方应答，不保证内部写入等操作已经完成 |
| ACK 由发送方产生 | ACK/NACK 由接收方产生 |
| 写完需要主机发送 NACK | 正常写完：从机 ACK，主机 STOP |
| 读完直接发送 STOP | 常见正常读流程：主机先 NACK，再 STOP |
| 重复起始发生在第 9 个时钟内 | 第 9 个时钟用于应答，重复起始另行产生 |
| 从机地址小就可以随时抢占 | 只能在同时竞争时参与仲裁，不能抢占已有通信 |
| 连续读写一定自动递增地址 | 是否支持地址自动递增，需要查看器件手册 |

### 9. 软件 I²C 与硬件 I²C

| 实现方式 | 工作方式 |
| --- | --- |
| 软件模拟 I²C | 程序控制 GPIO，产生时钟和数据时序 |
| 硬件 I²C | 使用 MCU 的 I²C 外设，由硬件完成主要时序 |

两种方式遵循相同的总线协议，但对仲裁、时钟拉伸等功能的支持，要看具体实现。

### 10. 复习口诀

> **起始高变低，停止低变高。**
>
> **低电平改数据，高电平保稳定。**
>
> **八位传数据，第九位来应答。**
>
> **谁接收，谁应答。**
>
> **写完 ACK 加 STOP，读完 NACK 加 STOP。**





## 二、FSMC 控制器与 LCD 驱动

### 1. 基本概念

FSMC 是灵活静态存储控制器，用于连接和访问外部存储器，例如 SRAM、NOR Flash 和 NAND Flash。

配置好引脚、地址映射和访问时序后，CPU 就可以通过访问对应的内存地址，由 FSMC 自动完成外部总线操作。

> FSMC 不只是读取外部存储器，也可以进行写操作。

### 2. 为什么 FSMC 可以驱动 LCD

带 8080 并行接口的 LCD 控制器，通常具有：

- 数据线。
- 片选信号。
- 读写控制信号。
- 命令和数据选择信号。

这些接口信号与 FSMC 的异步存储器接口相似。配置合适的读写时序后，FSMC 就可以与屏幕控制器通信。

> 关键不是单纯“支持异步”，而是 FSMC 的异步读写时序能够匹配 LCD 的 8080 接口要求。

### 3. FSMC 与 LCD 的信号连接

常见连接方式如下：

| FSMC 信号 | LCD 信号 | 作用 |
| --- | --- | --- |
| D0～Dn | D0～Dn | 传输命令、参数和像素数据 |
| NE | CS | 片选，选中屏幕控制器 |
| NWE | WR | 写控制信号 |
| NOE | RD | 读控制信号 |
| 某一根地址线 Ax | DC / RS | 区分命令和数据 |

其他信号，例如复位和背光控制，通常通过 GPIO 或其他外设控制，具体由硬件设计决定。

#### 命令和数据如何区分

以常见的连接方式为例：

- DC / RS 为 `0`：传输命令。
- DC / RS 为 `1`：传输数据。

实际电平含义需要查看屏幕控制器手册。

> 命令和数据都通过数据线传输，地址线只负责选择当前传输的类型。

### 4. 地址映射是什么

配置好 FSMC 后，外部器件会对应 MCU 地址空间中的一段区域。

CPU 访问这段地址时，FSMC 会将访问转换成外部引脚上的信号，包括：

- 地址线电平。
- 数据线电平。
- 片选信号。
- 读写控制信号。

连接 LCD 时，通常将一根地址线接到 LCD 的 DC / RS 引脚。因此，选择不同的访问地址，就可以让这根地址线输出不同电平，区分命令和数据。

```text
CPU 写命令地址
    ↓
FSMC 输出 DC / RS = 0
    ↓
数据线输出命令，并产生写脉冲
    ↓
LCD 接收命令

CPU 写数据地址
    ↓
FSMC 输出 DC / RS = 1
    ↓
数据线输出数据，并产生写脉冲
    ↓
LCD 接收数据
```

> 不是把屏幕每个像素的坐标直接映射为 CPU 地址，而是把屏幕控制器的命令、数据访问接口映射到 MCU 地址空间。

### 5. 16 位总线下的地址偏移

在常见的 16 位 FSMC 总线配置中：

- CPU 按字节编址。
- 每次 16 位访问占 2 个字节。
- 外部 FSMC 地址线 A0 对应 CPU 地址的 bit1。
- 外部 FSMC 地址线 Ax 对应 CPU 地址的 bit(x + 1)。

例如，将 FSMC 的 A16 连接到 LCD 的 DC / RS：

```text
A16 对应 CPU 地址 bit17

命令地址：基地址
数据地址：基地址 + 2^17
```

假设使用的片选区域基地址为 `0x60000000`，则可以采用：

```c
#define LCD_CMD_ADDR   0x60000000UL
#define LCD_DATA_ADDR  0x60020000UL

#define LCD_CMD   (*(volatile uint16_t *)LCD_CMD_ADDR)
#define LCD_DATA  (*(volatile uint16_t *)LCD_DATA_ADDR)
```

使用方式：

```c
LCD_CMD  = command;
LCD_DATA = data;
```

注意：

- 以上只是特定接线和配置下的示例。
- 实际基地址由使用的片选区域决定。
- 地址偏移由总线宽度和 DC / RS 所连接的地址线决定。
- `volatile` 用于要求编译器保留这些硬件访问，不能随意省略或合并。

### 6. 一次写操作如何完成

程序执行：

```c
LCD_DATA = color;
```

大致流程如下：

```text
CPU 向映射地址执行写操作
    ↓
FSMC 选中对应片选区域
    ↓
输出地址线状态，选择数据接口
    ↓
数据线输出颜色值
    ↓
产生符合配置要求的写控制脉冲
    ↓
LCD 控制器接收数据
    ↓
完成本次总线写入
```

具体的数据采样边沿和保持时间，需要满足 LCD 控制器手册的要求。

> FSMC 自动产生总线时序，但写什么命令、按什么顺序发送参数，仍由程序决定。

### 7. 如何向屏幕显示像素

屏幕控制器通常需要先设置写入区域，再接收像素数据。

以显示一个矩形区域为例：

```text
发送设置列地址的命令
    ↓
发送起始列和结束列参数
    ↓
发送设置行地址的命令
    ↓
发送起始行和结束行参数
    ↓
发送写显存命令
    ↓
连续写入像素颜色数据
    ↓
屏幕控制器更新显示内容
```

具体命令值、参数格式和像素格式，由屏幕控制器型号决定。

很多屏幕控制器在接收连续像素时，会自动更新内部写入位置，因此程序可以反复向同一个数据映射地址写入像素。

> CPU 访问的数据地址可以不变，改变的是屏幕控制器内部的像素写入位置。

### 8. 时序配置

FSMC 的时序参数需要根据 MCU 时钟和屏幕控制器要求设置。

常见参数包括：

| 参数 | 作用 |
| --- | --- |
| 地址建立时间 | 为地址和选择信号提供建立时间 |
| 数据建立时间 | 配合访问模式确定数据阶段及读写脉冲时序 |
| 地址保持时间 | 在相应访问模式下提供地址保持时间 |
| 总线转换时间 | 为相邻访问之间的总线切换提供间隔 |

具体哪些参数生效、如何换算时间，需要结合 STM32 参考手册中的访问模式和时序图判断。

配置不合适，可能出现：

- 屏幕初始化失败。
- 颜色或像素数据错误。
- 花屏。
- 读回数据异常。
- 访问速度过慢。

> 不能只追求速度，需要先满足屏幕控制器规定的时序。

### 9. FSMC 与 LVGL 如何配合

LVGL 负责绘制界面，显示驱动负责把绘制结果发送给屏幕。

```text
用户操作或业务数据变化
    ↓
LVGL 更新控件
    ↓
LVGL 渲染像素到绘图缓冲区
    ↓
调用显示刷新回调
    ↓
驱动设置 LCD 写入区域
    ↓
通过 FSMC 写入像素数据
    ↓
传输完成后通知 LVGL
```

需要区分三个作用：

| 部分 | 作用 |
| --- | --- |
| LVGL 计时基准 | 让 LVGL 知道经过了多少时间 |
| LVGL 处理函数 | 执行定时处理、动画和刷新等工作 |
| FSMC | 产生 LCD 接口的读写时序，完成总线访问 |

如果使用同步方式发送像素，就在发送完成后通知 LVGL；如果使用 DMA 等异步方式，就要等传输真正完成后再通知。

> 不能在像素尚未传输完成时，就告诉 LVGL 缓冲区已经可以复用。

### 10. FSMC 与 DMA 的区别

| 外设 | 主要作用 |
| --- | --- |
| FSMC | 将内存访问转换为外部器件的总线读写信号 |
| DMA | 按配置搬运数据，减少 CPU 搬运负担 |

仅使用 FSMC 时，如果程序循环写入像素，CPU 仍然参与每次写入。

```c
for (uint32_t i = 0; i < pixel_count; i++) {
    LCD_DATA = pixels[i];
}
```

在芯片和 DMA 配置支持的情况下，可以由 DMA 搬运像素到 LCD 数据映射地址，再由 FSMC 产生外部写时序。

> FSMC 自动产生时序，不代表自动搬运整个像素缓冲区。

### 11. 8080 接口为什么不需要持续像素时钟

带 8080 接口的常见 LCD 控制器，通过读写控制脉冲接收命令和数据。

对于带内部显示存储器的屏幕控制器：

- MCU 将像素写入屏幕控制器的显存。
- 屏幕控制器负责后续面板扫描。
- MCU 不需要持续向接口提供像素时钟。

这与需要持续提供像素时钟及同步信号的 RGB 接口不同。

### 12. 易错点总结

| 易错点 | 正确理解 |
| --- | --- |
| FSMC 只能读外部存储器 | FSMC 可以进行读写操作 |
| 只要是异步接口就能直接连接 | 还需要检查电平、位宽和读写时序是否兼容 |
| 命令通过地址线传输 | 命令通过数据线传输，地址线用于选择命令或数据 |
| 每个像素都对应一个 CPU 映射地址 | 常见做法是向固定数据地址连续写入像素 |
| FSMC 能自动理解屏幕命令 | 命令顺序和参数由软件组织 |
| 用了 FSMC，CPU 就不参与像素传输 | CPU 循环写像素时仍然参与，DMA 可以辅助搬运 |
| SysTick 决定屏幕写脉冲宽度 | 写脉冲由 FSMC 时钟、访问模式和时序参数决定 |
| 8 位和 16 位总线的地址偏移相同 | 地址线与 CPU 地址位的对应关系会随总线宽度变化 |

### 13. 面试口述版本

FSMC 本来是用于访问外部存储器的控制器，因为它的异步读写时序可以匹配 LCD 的 8080 并行接口，所以也能用来驱动屏幕。

连接时，数据线负责传输命令、参数和像素数据，片选及读写信号负责控制传输，再用一根地址线区分命令和数据。

配置好地址映射和时序后，程序就可以像访问存储器一样，向对应地址写入内容，由 FSMC 自动产生总线控制信号。

显示时，程序先发送命令设置屏幕的写入区域，再连续写入像素数据。上层 LVGL 负责绘制界面，底层显示驱动通过 FSMC 将像素发送给屏幕。
