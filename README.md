# 嵌入式知识点总结

## 一、I²C 通信协议

### 1. 基本概念

I²C 是一种支持多主多从的半双工同步串行通信协议，使用两根信号线：

| 信号线 | 作用 |
| --- | --- |
| SDA | 传输地址、数据和应答 |
| SCL | 提供时钟，通常由主机产生 |

基本特点：

- 每个字节为 **8 位，高位先发送**。
- 常见的从机地址为 **7 位**，后面加 **1 位读写位**。
- 读写位为 `0` 表示写，为 `1` 表示读。
- **从机地址**：决定访问哪个器件。
- **寄存器地址**：决定访问器件内部哪个位置。

### 2. 为什么使用开漏输出

SDA 和 SCL 通常采用 **开漏输出 + 上拉电阻**。

| 发送内容 | 引脚动作 |
| --- | --- |
| 发送 `0` | 主动拉低信号线 |
| 发送 `1` | 释放信号线，由上拉电阻拉高 |

只要有一个器件拉低，总线就是低电平，形成“线与”。

采用这种方式有三个主要作用：

1. 避免多个器件共用总线时，一个主动拉高、另一个主动拉低造成电气冲突。
2. 支持多主机仲裁。
3. 支持时钟拉伸。

> 上拉电阻和总线电容会影响信号上升速度。

### 3. 基本时序

| 信号 | 时序 |
| --- | --- |
| 起始信号 START | SCL 为高电平时，SDA 由高变低 |
| 终止信号 STOP | SCL 为高电平时，SDA 由低变高 |
| 数据传输 | SDA 在 SCL 低电平期间改变，高电平期间保持稳定 |
| ACK | 第 9 个时钟，接收方拉低 SDA |
| NACK | 第 9 个时钟，接收方释放 SDA，使其保持高电平 |
| 重复起始 Sr | 不先发送 STOP，直接再次产生 START |

#### 应答规则

每传完 8 位数据，第 9 个时钟用于应答：

- 发送方释放 SDA。
- 接收方在第 9 个时钟的高电平到来前准备好应答电平。
- 在第 9 个时钟的高电平期间，应答电平保持稳定。
- 发送方在此期间读取 SDA，判断 ACK 或 NACK。

> **谁接收字节，谁负责应答。**
>
> 重复起始不是在第 9 个应答时钟内产生的。

### 4. 写寄存器的过程

首先主机发送起始信号，再发送从机地址加写位，从机应答 ACK。

然后主机发送要写的寄存器地址，从机再应答 ACK。

接着主机发送数据，每发送一个字节，都由从机应答 ACK。如果还有数据，主机就继续发送；如果写完了，主机直接发送终止信号。

#### 时序流程

```text
主机发送 START
    ↓
主机发送从机地址 + 写位 0
    ↓
从机应答 ACK
    ↓
主机发送寄存器地址
    ↓
从机应答 ACK
    ↓
主机发送数据 1
    ↓
从机应答 ACK
    ↓
主机发送数据 2（如果需要继续写）
    ↓
从机应答 ACK
    ↓
主机发送 STOP
```

#### 注意事项

- 写数据时，**主机发送，从机接收并应答**。
- 正常写完，主机直接发送 STOP，**不需要主机发送 NACK**。
- 如果从机无法接收，可能回复 NACK，主机应根据情况结束通信或重试。

### 5. 读寄存器的过程

首先主机发送起始信号，再发送从机地址加写位，从机应答 ACK。

然后主机发送要读取的寄存器地址，从机应答 ACK。

接着主机发送重复起始信号，再发送从机地址加读位，从机应答 ACK。

然后从机开始发送数据。主机每接收一个字节，如果还想继续读取，就应答 ACK；如果已经读到最后一个字节，就发送 NACK，再发送终止信号。

#### 时序流程

```text
主机发送 START
    ↓
主机发送从机地址 + 写位 0
    ↓
从机应答 ACK
    ↓
主机发送要读取的寄存器地址
    ↓
从机应答 ACK
    ↓
主机发送重复起始 Sr
    ↓
主机发送从机地址 + 读位 1
    ↓
从机应答 ACK
    ↓
从机发送数据 1
    ↓
主机应答 ACK（继续读取）
    ↓
从机发送数据 2
    ↓
主机应答 NACK（最后一个字节）
    ↓
主机发送 STOP
```

#### 为什么先写再读

前面的写操作，是为了告诉从机：

> 接下来要读取哪个寄存器。

后面通过重复起始，切换为读操作。

> 这是常见的寄存器读取流程，具体操作由器件数据手册规定。

### 6. 多主机仲裁

多个主机同时开始通信时，会 **边发送、边读取 SDA**。

仲裁规则：

1. 双方发送的位相同，就继续发送。
2. 遇到第一个不同的位，发送 `0` 的主机继续。
3. 发送 `1` 却读到 `0` 的主机仲裁失败，停止竞争并释放 SDA。

#### 举例

```text
发送顺序：从左到右

主机 A：1  0  1 …
主机 B：1  0  0 …
总线  ：1  0  0 …
              ↑
      A 想发 1，却读到 0
      A 仲裁失败，B 继续
```

并不是提前规定谁发送 `0`、谁发送 `1`，而是由各自准备发送的地址或数据决定。

#### 地址和优先级的关系

在同时竞争、地址格式相同且地址不同的情况下：

- 访问较小从机地址的主机会获胜。
- 如果地址相同，还可能继续在读写位或后续数据中分出胜负。
- 如果发送的内容一直相同，就可能一直无法分出胜负。

> **地址小不能抢占已经开始的通信。**
>
> 总线已经被占用时，其他主机必须等待。

### 7. 时钟拉伸

主机释放 SCL，准备让它变高时，支持时钟拉伸的从机可以继续拉低 SCL，让主机等待。

等从机准备好后，再释放 SCL，通信继续。

```text
主机释放 SCL
    ↓
从机还没准备好，继续拉低 SCL
    ↓
主机检测到 SCL 仍为低，等待
    ↓
从机准备好，释放 SCL
    ↓
SCL 被上拉为高，通信继续
```

> 支持时钟拉伸的主机，需要读取 SCL 的实际电平，不能只根据自己的输出动作判断时钟已经变高。

### 8. 易错点总结

| 易错点 | 正确理解 |
| --- | --- |
| 从机地址和寄存器地址混淆 | 从机地址选器件，寄存器地址选器件内部的位置 |
| ACK 就代表全部操作完成 | ACK 表示接收方应答，不保证内部写入等操作已经完成 |
| ACK 由发送方产生 | ACK/NACK 由接收方产生 |
| 写完需要主机发送 NACK | 正常写完：从机 ACK，主机 STOP |
| 读完直接发送 STOP | 常见正常读流程：主机先 NACK，再 STOP |
| 重复起始发生在第 9 个时钟内 | 第 9 个时钟用于应答，重复起始另行产生 |
| 从机地址小就可以随时抢占 | 只能在同时竞争时参与仲裁，不能抢占已有通信 |
| 连续读写一定自动递增地址 | 是否支持地址自动递增，需要查看器件手册 |

### 9. 软件 I²C 与硬件 I²C

| 实现方式 | 工作方式 |
| --- | --- |
| 软件模拟 I²C | 程序控制 GPIO，产生时钟和数据时序 |
| 硬件 I²C | 使用 MCU 的 I²C 外设，由硬件完成主要时序 |

两种方式遵循相同的总线协议，但对仲裁、时钟拉伸等功能的支持，要看具体实现。

### 10. 复习口诀

> **起始高变低，停止低变高。**
>
> **低电平改数据，高电平保稳定。**
>
> **八位传数据，第九位来应答。**
>
> **谁接收，谁应答。**
>
> **写完 ACK 加 STOP，读完 NACK 加 STOP。**
